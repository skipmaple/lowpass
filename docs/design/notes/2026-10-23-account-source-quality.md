# 账户头像失败回退与周刊来源标题换行

本轮基于 main `c1f47954`，修复两处真实页面反例，不包含待审 PR69–80，不修改账户认证或已发布内容。

## 账户信息头像

真实 Settings/Show GET 的 provider 头像地址非空但加载失败时，原实现只判断 URL 是否存在，浏览器留下破图。新增局部 AccountAvatar：error 后显示原有 20px 人像图标；以 URL 为 key，其他字段更新不重新请求已失败地址，URL 改变、清空或重新挂载后可以重试。显示名、邮箱、角色、装饰性 alt 与 no-referrer 保持。

前端回归先出现四个预期失败，修复后 Settings 18 项、全前端 459 项、类型检查与生产构建通过。独立 GET 验收以真实 error / load 事件区分失败和成功；成功图使用明确的浏览器层测试 PNG，不代表 provider 可用性。

## 周刊来源标题

真实来源「阮一峰科技爱好者周刊」在 320px 的 193px 标题列中普通换行成为九字加单独的「刊」。h2 本身已有 block，问题是没有纳入 T2 的既有均衡换行。仅把 `.source-band-title` 加入已有选择器，保留文字、字体、字号、图标、横带、期号和原文链接。

真实 Rails / React / Chrome 系统回归先在末行一个汉字处失败（1 项 /18 断言），相同测试随后通过（1 项 /20 断言）。原生生产构建与真实 GET 在 320px 排成五字加五字，375px 保持单行；实际文楷字形、几何与动作检查通过。桌面、打印及任意来源名不能由这两宽外推为全量通过。

## 证据与交付边界

会话外部证据目录：`account-avatar-quality/`、`source-heading-quality/`、`account-source-peer-review/`。原失败、修正的探针预期与历次运行均保留；冻结输入由真实控制器 GET 产生，候选由实际 Rails layout/helper 与当前 Vite manifest 渲染，仅更新 envelope version。自有无头 Chrome 的本地 GET 检查不替代用户 Chrome、跨平台或生产验收。

组合后完整本地 CI 通过：459 项前端、856 项 Rails /3763 断言、78 项系统 /8064 断言，首屏 264.57 KB，总耗时 60.98 秒。最终同一生产构建从实际 Rails layout/helper 导出账户与周刊两个真实 GET envelope，SQL 事件为零、props 原样保留；85 个源码与179 个静态资产 pin 在验收前后吻合。

最终构建的四个头像场景（375/1440、自然 error 与明确的测试 PNG load）通过；两个来源标题场景（320/375）33 次断言通过，root 实际查看了头像占位、成功图和两宽来源横带截图。成功 PNG 只测试图像解码与排版，不代表 provider 的真实可用性；报头头像的独立旧缺口属于 PR78，未在本次冒称已修复。
