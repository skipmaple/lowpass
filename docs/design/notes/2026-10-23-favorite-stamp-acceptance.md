# 收藏盖章只跟随被接受的操作

M3 的真实生产构建重放发现：已收藏条目点击取消，在 DELETE 尚未结束时再次点击同一书签，再让取消失败，状态会正确回到已收藏，却额外盖章一次。375px 普通动态的有界反例只有一个 DELETE、没有 POST；失败回滚后出现 `data-stamp`、`lp-press` 的 animationstart 与 0.92 → 1 的实际缩放帧。

Provider 已有的去重正常工作。问题在 FavoriteButton：它先改局部 stamping，再调用可能忽略本次操作的 toggle，被忽略的点击仍留下了局部盖章状态。

## 修正与契约

点击前后读取实际 has，仅在同步乐观 toggle 确实改变收藏状态时更新 stamping；当状态退回未收藏，同时清除本次盖章资格，防止外部状态复活它。不改变 Provider 接口、请求去重、失败提示、收藏页恢复凭据或网络协议。正常收藏仍涨墨并轻压，取消和失败回滚沿用已有裁切；被忽略的点击不再中断或补出盖章。CSS、240ms 令牌和减少动态规则不改。

依据是 `docs/superpowers/specs/2026-10-14-award-quality-design.md` 的 M3 及 PRD D34、R-10.5。Provider 的 has 每次读取 ref，接受操作后同步 mark；异步响应不会插入同一段同步点击处理。原有在途操作不排队补做最后一次点击。

## 回归

旧组件的 24 项基线先通过。增加三个针对状态边界的用例后，旧源码为 3 failed / 24 passed：添加 pending 再点会摘去盖章，取消 pending 再点会在失败回滚时盖章，无 itemId 的忽略操作会给后来带入的已收藏留下盖章。修正后连同收藏页回归为 44 passed。测试使用真实 Provider，仅替代出站 fetch。

初版 6fdc6eb 的完整 `bin/ci` 一次退出 0（70.34 秒）：457 项前端、856 项 Rails（3763 assertions）、77 项系统（8044 assertions）。首屏 264.59 KB / 300 KB；现有两项 Vitest moderate 告警保留，high 门禁通过。随后补充的外部状态边界另按新源树验收。

浏览器基线保留真实 Daily/Show、27 条冻结内容、实际 Rails 模板 / helper 与生产模块。仅用户和收藏初态为夹具；HTTP 明确 UTF-8，全部写请求由本地内存响应。375 / 1440 与正常 / 减少动态各一组，分别观测添加成功、取消成功、添加失败和取消失败；自然 rAF 读取裁切、缩放、动画对象及事件，保留录屏，不改动画时间或样式。

候选重放保留四组核心上下文的 16 次操作，并增加两个 375px 普通动态单例：原来的取消连点失败恢复 `on=true / stamp=false`，没有新 lp-press；添加 pending 时的第二次真实鼠标点击间隔 80.7ms，当时 lp-press 仍在运行（约 50ms / 240ms），仍只发一个 POST、没有 DELETE，首次盖章没有被取消且正常结束。原始基线与候选材料分开保存，不把两个有界连点单例扩展为所有浏览器的结论。

初版候选只改变 FavoriteButton 的点击处理；后续补丁增加未收藏时清除盖章资格，相关 Provider 和 CSS 源字节仍保持 main 基线。重放使用各自产物的真实入口，不能因组件共用而声称所有页面的收藏动效均已验收。

## 失败之后的外部状态同步

初版仍有第二个可达边界：一次被接受的添加失败后，`on=false` 隐藏了 data-stamp，却保留了局部 stamping=true。搜索页的来源、刊物与日期筛选显式 preserveState，结果按 item_id 保留身份；同账号在别处成功收藏后，筛选响应可把原按钮变回已收藏，旧盖章也随之复活。普通新查询、排序和分页并非都保留状态，不能泛称所有导航均可复现。

真实 Search/Show 生产模块在 375/1440 × 正常/减少动态四个上下文复现。冻结的实际 Tailwind 条目组成一条匹配结果，POST 500 和后续 GET 都由本地内存响应；GET 的 favorites=[H] 模拟其他入口已完成收藏，不声称执行了真实第二标签页写入或服务器搜索。实际点击「日刊」筛选，原按钮身份不变，外部同步阶段没有新书签点击，却出现一次 lp-press。正常动态记录 240ms 声明及自然缩放，减少动态仍按既有 1ms 规则，不能把事件发生等同肉眼看见同等动画。

补充两项真实 Provider 回归：添加失败后同实例接收新 props，以及失败后同 hash 的另一按钮接受添加。旧实现 2 failed / 27 passed，修正后连同收藏页 46 passed。on=false 时条件调整本按钮的局部 state；下一次外部 on=true 只填墨，自己的下一次添加仍可盖章。不重挂按钮，不增加请求，不通过延后 effect 清理来容忍中间旧标记。实现参考 React 的[条件调整本组件 state](https://react.dev/learn/you-might-not-need-an-effect#adjusting-some-state-when-a-prop-changes)。

追加补丁完整 `bin/ci` 退出 0（62.96 秒）：459 项前端、856 项 Rails / 3763 assertions、77 项系统 / 8044 assertions，首屏 264.59 KB。候选真实筛选路径四个上下文均保留原节点和已收藏终态，外部同步阶段无新盖章事件、无缩放，普通动态仍记录填墨中间帧。每组只有一个被夹具返回 500 的 POST，没有为了同步额外添加请求。

同一候选构建另外复跑原 Daily 矩阵：四个上下文的 16 次添加/取消/失败操作、375px 取消 pending 连点失败和添加 pending 连点两个单例均通过。添加期间第二次真实鼠标点击间隔 80ms，当时原 lp-press 在约 50ms / 240ms，保持一次 POST、没有中断动画；取消失败连点仍恢复实心且不盖章。正常核心操作各有 14–28 个填墨/退墨中间帧，减少动态样本未见缩放；读到的 0 条 longtask 仅限这些有界窗口，不外推性能保证。

捕获副本固定 641 份源码与 169 份构建目录文件，实际请求到的 37 个静态资源按内容校验；构建目录文件数量不当作当前页面加载量或资源预算。后续只补写这两份说明文档的验收结果，不以文档变化重跑或替换运行证据。独立审查未发现阻塞问题；远端新 head 的状态以 PR 检查和对应回执为准，初版的通过不能代替它。

## 验收边界

保留节点的书签可观测连续涨墨、退墨与回滚。收藏页会立即把取消的书签替换为「已取消收藏 / 恢复」，恢复则新挂载按钮；该路径不能拿来证明原按钮完整退墨，也没有新增恢复盖章要求。PRD R-10.7 与收藏设计 K4/K8 专门要求这一立即状态和焦点交接；M3 没有明确撤销它。独立契约审查认为仅凭卸载不足以认定必须修的缺陷，但这属于交叉阅读的兼容解释，不能改写成 M3 原文明示了豁免。本补丁保留该专项交互，不延迟恢复入口/焦点或额外制造退出图形；收藏页的实际状态与焦点验收仍须单列。

减少动态的 CSS 声明仍为 1ms，运行验收按实际可见帧与终态判断，不能写成所有 animation-name 都为 none 或严格数值 0ms。动画窗口的本地 longtask 观测不外推冷载、全站或统计性能保证。
