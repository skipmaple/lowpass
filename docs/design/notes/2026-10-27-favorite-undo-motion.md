# 收藏页取消与恢复：保留墨层

依据已批准的奖项品质设计 M3 和 PRD R-10.7：取消退墨，恢复立即可用，不为动画延迟操作。

原收藏行在取消时把 `FavoriteButton` 整个换成状态和恢复按钮，原墨层也随之卸载，无法完成已有的退墨过渡。本轮保留同一个组件、按钮和墨层，取消后在描线书签左侧立即显示既定文案「恢复」。恢复仍交给原 Provider，使用原签名凭据、请求去重和在途排队；焦点跟随限制不变。服务端返回 204 时原有的行消失规则保持，不为动画留下不可恢复的假记录。

按钮只允许颜色过渡。第一版自动化 Chrome 在减少动态模式下发现，全局 1ms 规则会把新内边距也变成过渡，造成一帧 13px 墨层错位；新增系统回归先真实失败于 `padding-right`，再限定过渡属性。最初单独启动该回归时未设置与完整 CI 相同的 `CI=true`，登录页未挂载、零断言报错；这次环境失败保留，未计为有效 RED。

验证：旧实现的 DOM 保留回归为 1 失败 / 17 通过；保留墨层修正版完整 CI 为 639 项前端、997 项 Rails / 4594 断言、138 项系统 / 9988 断言，零失败。首屏 268.56KB；相对 PR #97 的同口径资源，JS gzip 增加 51B、CSS 增加 71B。

固定两条收藏的隔离自动化 Chrome 覆盖普通 320/375/1440、减少动态 375、取消失败、恢复失败和在途恢复七个上下文。逐帧 CSS 采样确认同节点持续连接、普通裁切经过中间态、减少动态采用既定 1ms 终态规则、描线和墨层对齐且没有布局属性过渡；在途恢复的一次可信点击落在取消后约 23ms，最终正常恢复。补查其余七宽后，320、375、390、481、600、768、1024、1440、1920、2560 的取消后布局均无横向溢出或文字／图标重叠，恢复目标至少 44px。

直接恢复同步换态时沿用盖章资格；排队恢复后来才填墨，不追加延迟盖章或扩展 Provider。第一版减少动态错位的原始记录与首次完整 CI 均保留，修正后重跑是不同源码的回归检查。

后续原生 Space 键复查另发现：恢复文字继承图标按钮的 -6px 内缩轮廓，焦点边线压到文字。恢复态改用既有文字按钮的外侧 2px 轮廓；系统回归改为原生键盘输入，并直接验证轮廓完整包住文字，先在旧样式真实失败。上述完整 CI 数字保留为墨层修正版的记录，后续补丁的检查与发布状态单独记账，不覆盖旧判定。

这是限定输入的本地自动化浏览器证据，不是产品负责人 Chrome 的生产录屏、真实手机／Windows 或任意数据的证明。完整 M3 与原始 60 项仍未整体闭合；模型和历史内容未改，也未发起实网模型调用。发布状态以对应 PR 和部署回执为准。证据目录：`favorite-undo-motion-20261027`。
