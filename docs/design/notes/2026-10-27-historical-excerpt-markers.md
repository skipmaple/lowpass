# 旧日刊摘要的省略提示

第 2026-10-27 日刊的七条 Hackaday 摘要在页面中缺少省略提示；早上装订时运行的旧清洗规则会移除 `read-more` 链接，当天稍后合并的清洗修复只作用于以后抓取，不修改已发布记录。原始装订时的源站响应没有留存，无法断言当时的响应确有省略提示。当前页面显示已存摘要全文，没有 CSS 截断。旧版摘要存储与展示不包含可可靠推导“源站原本有省略号”的标记，不能从缺少句号直接推断。

本候选只对已发布的该期七条做独立展示核验：第 1–4 条与 2026-10-27 15:44 保存的 Hackaday RSS 快照按标题和链接唯一匹配；第 5–7 条与同日稍后取得的对应文章 WordPress 摘要接口按标题和链接唯一匹配。所有源摘要都含明确的 `…read more`，使用现行清洗器清洗后恰好等于已存摘要加一个空格和省略号。快照及其 SHA-256 见 `script/historical_excerpt_fingerprints`，使用私密只读条目快照和固定源文件可重新生成七个指纹。源站这些后来观察到的摘要与已存摘要匹配，并不能证明早上装订时获取到的源码版本。

展示规则要求已发布日刊的期键、期 ID、源 ID、条目 ID、排序、标题、链接和完整摘要的指纹全部匹配，才在页面数据副本追加 ` …`。来源 ID、条目身份或摘要改变、重抓产生新 ID、未发布、其他期和其他来源均不匹配，维持原样；当前来源名称或 feed 配置的变化不参与指纹。不会在线请求源站、写入刊期或条目、更新收藏、搜索索引或调用模型；搜索与收藏仍显示各自已有的数据。证据复现路径位于任务的 `historical-excerpt-evidence-20261027/`，其中只读数据库快照及上游响应均设置为仅用户可读。

本地模拟 375/1440 宽度使用隔离测试库和七条已发布摘要，页面逐条显示源站省略提示，数据库原始摘要不变；未通过真实手机或 Windows 设备验证。

实现前对生产进行了两次只读、可重复读查询，筛选 `published` 日刊、RSS 源和可见条目，两次七条字段一致。只读 SQL 与快照位于上述私密证据目录；首次快照 SHA-256 为 `da311b0b44416febaccb23be94ed51b7fd61b761eae84f0ddd65d9fac3141415`。独立复核可重算源证据和指纹；快照本身仍不能单独证明早上装订时上游响应的形态。

非法 UTF-8 只在匹配器中被拒绝，不表示整条页面已具备非法编码容错：回退后既有 `SummaryCleaner.stored` 仍可能抛错。正常 PostgreSQL UTF-8 存储不会产生此类记录；本次不改变既有清洗规则。
