# 登录启动与减少动态首帧

依据 PRD 6.4 与奖项品质设计 M6，登录按钮不应等待日出动画，减少动态效果时日出直接呈现终态。

独立匿名 Chrome 的生产记录显示：按钮从首次采样就可命中，Google 和 GitHub 的原生提交事件均能在日出尚未结束时触发（请求在浏览器端取消，没有联系登录服务）。但登录页仍在应用入口执行后串行请求一份页面脚本；六个限定样本中，该请求耗时约 180–858ms。这是额外请求的实际耗时，不是可直接归因的整页加速数值。

登录页沿用现有日刊、周刊的入口加载方式。其他后台与次要页面仍按需加载；登录表单、身份验证与导航协议保持现有行为。新增代码和首屏体积继续按实际构建产物检查。

生产减少动态样本还记录到：最初两次样式采样仍为太阳下移 34px、光芒／水纹裁去的起始姿态，之后才进入终态。仅将动画缩成 1ms 仍会创建起始帧。日出是纯 SVG，没有依赖 `animationend` 的产品代码，因此减少动态时直接关闭其动画，使初次计算样式即为原始 SVG 的终态。其他依赖事件收尾的动画保留现有规则，普通日出的时长、字形、位置和配色不变。

`test/system/login_loading_test.rb` 使用真实页面验证两件事：登录页没有入口后新增的同源脚本请求；减少动态时第一次计算的太阳位移、光芒和水纹裁切均为终态。旧源码两项均失败，修正后通过。首次计算样式不是物理显示面板的录像，原生表单事件也不代表真实 OAuth 往返已完成；这两类边界不扩写成验收通过。
