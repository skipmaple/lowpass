# 期头在普通字库迟到时保持稳定

冷启动记录发现日刊大字日期及旁边说明在字体到达后移动。实际日刊、周刊页面的受控回归进一步区分了来源：移除普通网络字体后，单独恢复 Maple 没有改变所测位置；恢复文楷会改变日期字形的位置、宽度和旁边说明的位置。日期里的数字按既有排版规则与年月日整段使用文楷，回退字体的宽度不同。

从现有文楷 ui 字库切出 `0123456789 年月日第周` 共 16 个字形，保留原字形、水平度量和字体的垂直度量，随应用样式内联。声明放在普通 ui 字库之后，因此这些重叠码位优先使用相同字形的小切片。普通字库仍为其余界面文字服务；无需新增字体请求、等待整套字库或推迟显示页面。四个字体角色、字号、行高及页面结构保持现有规则。

生成方式仍为 `script/subset_fonts`。它先生成普通 ui 字库，再从 ui 提取日期切片；Vite 的 `?inline` 保证这份小切片进入样式。原有首屏 300 KB 门禁及新增 CSS 4 KB gzip 的要求继续适用，内联字体字节计入 CSS。

`test/system/period_font_stability_test.rb` 在真实页面中延迟普通字体，分别恢复 Maple 和文楷，比较日期字形、标题框及说明框的几何。覆盖 320、375、1270、1920px 的日刊与周刊。它验证字体替换时的稳定性；实际首次绘制和生产冷启动仍需要独立检查，不能据此宣称整个站点 CLS 恒为零。
