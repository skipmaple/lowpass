# 三主题前端预算决议

2026-11-06，产品负责人明确批准两项调整：首屏上限从 300 KiB 改为 **500 KiB**；A/B/C 三主题清理后的全部交付 CSS 建立一次性固定基线。旧的单主题 CSS 基线无法表达已确认的三套完整字体与视觉设计，因此本次记录新基线，而不删减字形、字重或覆盖来凑旧预算。

## 首屏统计

`script/first_screen_size` 分别统计 A 层叠清晨、B 双声部、C 展开阅读，每套都必须不超过 500 × 1024 字节。口径包括应用入口、日刊页面及静态依赖的 JavaScript 和关联 CSS、独立的应用 CSS、当前主题内容字体声明，以及该主题首屏壳字体。JS/CSS 使用逐文件 gzip BEST_COMPRESSION；WOFF2 按实际文件字节计；重复资源只算一次。

页面拆出的日刊 CSS 仍计入首屏，后台异步 CSS 不计入首屏，但必须计入下面的全站累计预算。正文 Unicode 字形分片依具体刊期按需请求，其实际网络成本仍需在浏览器验收中另列；500 KiB 不是整页所有正文传输量。

## 全站累计预算

- JavaScript：继续使用 `vendor/frontend-budget/aee2d5f.json.gz` 的原始逐文件资源，包 SHA-256 与内容 SHA-256 校验不变；累计增长上限仍是 **+3072 字节**。
- CSS：冻结本次清理后 production manifest 引用的全部 CSS，保存为 `vendor/frontend-budget/abc-themes-2026-11-06.json.gz`；累计增长上限仍是 **+4096 字节**。
- 两项都以同一 Ruby/Zlib 运行时分别重压缩基线原字节和当前产物，避免把某台机器的历史 gzip 总数作为跨平台常量。异步页面和后台资源都计入；本地遗留但不在当前 manifest 中的旧指纹文件不计入。
- 基线包与逐文件指纹不符、当前资源缺失或超过增量上限均失败。后续 PR 不得自动重置基线；再次调整需要单独的产品决议。

CSS 冻结包记录源 manifest 指纹、资源原字节、路径和 SHA-256；只作为审计与重新计量的数据读取，不执行。最终生产构建完成后再生成冻结包并固定脚本中的包指纹，不能把开发中间产物作为已接受基线。

## 字体边界

本次预算调整没有修改字体二进制、字体搭配、字重、字形覆盖或已有字符的分片选择。针对 `unicode-range` 空洞的压缩探索只做了临时量化，未落地范围扩张。旧验收文档中的 300 KiB 测量值保留为历史记录；当前门禁以本决议和 PRD N-1 为准。
