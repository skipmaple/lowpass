# 阅读入口与编辑理由 · 品质迭代

承接已上线的 PR #66（`2b865059`）。整体评审仍未接受“能获奖品质”的结论：手机首条标题出现偏晚，独有的推荐理由缺少具体判断依据。本轮保留既定纸墨、字体角色、单栏、三格来源目录、正文行距及条目上下 24px。

## 1. 手机阅读入口

- 在容得下的手机宽度，把日期与三个 44px 翻期图标放在同一行，日期属性/发布时间另成紧凑一行；320px 自然回退，不能挤压日期或操作目标。
- 复用 PageHead；桌面及归档语义保持一致。明确连续来源正文无额外上边距（基线实测已经为0，不计作提前量），适度收紧首栏前留白。
- 不隐藏来源标题，不改变标题整宽换行，不改变正文密度。
- 验收：375×844 同数据首条标题比原版本至少提前约 60px；320–2560 全断点无横溢、完整日期信息、唯一 h1、原生导航和焦点均保留。周刊和两类归档复查。

## 2. 推荐理由的判断依据

- 保留理由字段、20–60字、领域白名单、源排序、同次调用译文和发布解耦。
- 提示词要求引用输入中的具体信号与画像关键词的关系；低相关如实说明边界。不得把热度、语言、标题暗示升级成未提供的功能/性能/安全事实。
- 不重生成已发布理由，不改已发布条目。测试不碰网络；若做独立模型评估，先确认预算、敏感信息与持久化边界，再由独立评审对照输入评价。

此提示词候选已撤回，不随手机入口交付。固定九对真实输入的18次实际请求均通过结构解析，但独立盲评发现3条最终展示被截成半句，另有把标题暗示当作实现细节、把画像关键词当作项目功能的无据推断。更具体的指令没有证明质量提升，不能以Parser成功或CI通过替代编辑验收。现有20–60字/超长截断契约未改；后续应单独验证更简洁、严格区分事实和用途候选的方案。

## 3. 当前证据与继续验收

- 原生 Safari 和独立 Firefox 补测另行记录；单个引擎/版本不冒充 PRD N-7 全矩阵。
- 旧刊残留按生产实际内容定位；本地样本不能证明生产有同样问题。任何已刊重抓只准备具体方案，不执行未经批准的替换。
