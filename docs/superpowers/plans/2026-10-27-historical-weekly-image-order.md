# 历史周刊图文展示索引实施计划

> **执行方式：**本线程原生实现和本地验收；后续已批准第 416 期在远端检查全绿后合并并验收生产，不发起模型请求。

**目标：**在不改历史刊期、条目和收藏的前提下，为第 416 期经逐项核对的图片恢复原文相对段落位置。

**结构：**离线生成每期静态索引；服务端只在身份和内容精确匹配时给周刊 props 副本增加位置，继续使用现有 `WeeklyContent`。生成器不联网、不改生产；索引缺失或不可信回退。

**技术：**Rails 8、PostgreSQL 18、Ruby JSON / SHA-256、React；[已批准设计](../specs/2026-10-27-historical-weekly-image-order-design.md)。

## 全局约束

- 第 416 期可在远端检查全绿后合并部署；不主动调用模型、不写生产数据或自动读取上游，不扩展其他刊期。
- 索引不存原始数据库 ID、正文、图片或图片 URL；期和条目时间、搜索及收藏不得改变。
- `image_positions` 键已存在时，包括 null，绝不覆盖；全部失败按现有全文后配图回退。
- 正文长度按 JavaScript UTF-16 单位、小于 50000；段落按 `split('\n')` 含尾空段，空段回退；图片数 1–128、URL 完整合法且不重复，位置整数有序且不越界。

## 重点反例

- 同内容重抓的新 Item / Issue / Source ID 不能复用旧位置。
- 索引缺失、坏 JSON、未知版本、重复对象键或跨文件重复查找键不能让页面 500。
- `image_positions` 不存在、显式 null、非法数组必须区分。
- emoji、空段、末尾换行和 UTF-16 边界要与浏览器处理一致。
- 有效但错误的位置数组不能靠身份指纹检出；固定源文件与只读快照必须能重新生成相同索引，逐条复核。
