**默认假设（未收到异议，视为成立）**

- 时区统一为 Asia/Shanghai；界面中文，条目保留原文语言。
- 用户规模：站长本人加少量邀请用户，不超过 100 人；单管理员。
- 单人业余开发，优先"稳定跑起来"，其次才是功能广度。
- 技术选型由产品负责人自行决定；本文只写需求与约束，不做推荐。

## 1. 背景与目标

### 1.1 问题

- 技术动态分散在 Hacker News、GitHub Trending、Hackaday 等站点和邮件订阅里，每天来回切换，噪音多，也没有"看完即止"的边界。
- 看过即忘：一两周前在周刊里看到的工具，想再找时要翻多个来源的历史页。
- 现成方案不合身：RSS 阅读器不能按日、周"装订成刊"；Newsletter 不可自定义源；两者的搜索都弱，对中文更弱。

### 1.2 定位

把分散的技术信息源装订成"每日一期、每周一期"的个人刊物：可配置、可回溯、可搜索。

### 1.3 MVP 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 每天早上一处读完当日精选 | 日刊在 06:30 前可读的天数占比 ≥ 99% |
| G2 | 不改代码即可增减常见信息源 | 新增一个 RSS 源耗时 ≤ 3 分钟，无需发版 |
| G3 | 历史内容随手可找回 | 典型查询 30 秒内定位到条目；搜索 p95 延迟 < 500 ms |
| G4 | 维护成本低到可以长期跑 | 单源失败不阻塞发布；失败必有告警；每月人工维护 < 1 小时 |

### 1.4 非目标（MVP 明确不做）

AI 摘要与翻译、收藏与已读状态、评论点赞等社交功能、邮件或 RSS 推送输出、移动 App、原文全文转载与离线缓存、多语言界面、付费订阅。

其中 AI 摘要与翻译、收藏与已读状态只是本期不做，作为后续迭代候选（D6、D7）；其余暂无规划。

## 2. 目标用户与场景

技术从业者或独立开发者，中英双语阅读，每天早晨花 10 到 20 分钟看技术动态，周末读周刊。首位用户是站长本人，其余是少量邀请进来的同好。

- **S1 早间速览**：07:30 打开首页，看到今天的日刊三栏：HN、GitHub Trending、Hackaday。扫一遍标题，点几条跳原文，10 分钟结束。
- **S2 周末补课**：周六打开最新一期周刊，按"科技动态、文章、工具、资源"等板块浏览，感兴趣的跳原文。
- **S3 找回记忆**："上周日刊里那个 Rust 写的终端工具叫什么？"搜 `rust terminal` 或"终端 工具"，模糊命中条目，一键回到所在那一期。
- **S4 调整口味**：不想再看 Hackaday，在设置里取消勾选（P1）。发现一份新周刊提供 RSS，管理员在后台添加为周刊源，下周自动出现。
- **S5 出问题时**：某天 GitHub Trending 页面改版导致抓取失败。日刊仍按时发布，该栏显示"今日抓取失败"，管理员收到告警，修复后手动重抓补齐。

## 3. 核心概念（统一用语）

| 概念 | 定义 | 例子 |
|---|---|---|
| 信息源 Source | 一个可抓取的内容来源，等于适配器类型加配置 | HN Top（API）、GitHub Trending（网页）、Hackaday（RSS）、阮一峰周刊（GitHub 仓库） |
| 刊物 Publication | 按固定周期发布的合集，MVP 固定两种 | 日刊、周刊 |
| 期 Issue | 刊物在某个周期的一次发布，发布后内容不可变 | 日刊 2026-09-07；周刊 2026-W36 |
| 条目 Item | 期内的最小内容单元：标题、链接、摘要、来源、元数据 | 一条 HN 帖子、一个仓库、一篇 Hackaday 文章、周刊里的一条推荐 |
| 抓取任务 Fetch Run | 对某个源的一次抓取执行及其结果 | 成功或失败、条目数、耗时、错误摘要 |

关系：一期由该周期内所有启用源产出的条目按源分组构成；每个条目同时归属一个源和一期。

## 5. 功能需求详述

### 5.1 日刊

**生成规则。** 每日 06:00 触发，并行抓取所有启用的日刊源；全部完成或到 06:20 超时，即生成并发布当日一期。发布后条目不可变；管理员手动重抓某源会整栏替换，并在页面标注"已于 hh:mm 修订"。"今天"按 Asia/Shanghai 定义，每个自然日恰有一期；缺失时页面显示"本期未生成"，并给管理员补抓入口。

| 源 | 默认取数 | 条目展示字段 |
|---|---|---|
| Hacker News | Top Stories 前 30 条 | 标题跳原文；分数、评论数（跳 HN 讨论）、作者、发帖时间 |
| GitHub Trending | since=daily，全部语言，前 25 个 | 仓库名跳仓库；描述、主语言、总 star、今日新增 star |
| Hackaday | RSS 中近 24 小时发布的文章，上限 20 | 标题跳原文；一句摘要、作者、发布时间、封面图地址（可选） |

**可配置项。** 条数、语言过滤（GitHub）、最低分数（HN）、时间窗口（RSS）、栏目顺序。

**页面。** 顶部为日期与前后期导航；按源分栏，顺序可配置，移动端纵向堆叠；每个条目一行标题、一行摘要、一行元数据。

**降级。** 某源失败时该栏显示"今日抓取失败，已通知管理员"；全部失败时仍生成当日期并标记"空刊"，首页给出提示。

### 5.2 周刊

- **新期检测。** 每日 09:00 检查一次各周刊源是否有新期（阮一峰周刊通常周五发布），发现即抓取并发布。
- **阮一峰周刊解析。** 从 GitHub 仓库 `ruanyf/weekly` 读取该期 Markdown；按二级标题拆板块（本周话题、科技动态、文章、工具、资源、图片、文摘、言论等），板块内按编号条目拆分；每条目取标题、首个链接、前 200 字摘要、所属板块。解析失败时降级为整期一条加原文链接，并告警。
- **通用 RSS 周刊源。** 每条 feed 记录视为一期，一期一条目（标题、摘要、链接），不拆分。
- **周期键。** ISO 周，如 2026-W36。同一周内多个周刊源合并在同一期页面，按源分节，各源保留自己的期号与标题，如"第 N 期：……"。
- **页面。** 期标题、发布日期、板块目录锚点、条目列表、原文链接；前后期导航；归档按周列表。

### 5.3 信息源配置（管理员）

- **源列表。** 名称、适配器类型、所属刊物、状态、上次抓取结果、下次抓取时间。
- **新建与编辑。** 选适配器（Hacker News、GitHub Trending、RSS/Atom、阮一峰周刊），填参数，点"测试抓取"预览前 5 条，保存。
- **通用 RSS 参数。** feed 地址、所属刊物、最多条目数；日刊源的时间窗口默认 24 小时。
- **抓取记录。** 最近 50 次运行的状态、条目数、耗时、错误摘要；一键重抓。
- **停用而非删除。** 停用后不再抓取，历史条目保留可搜。MVP 不提供删除，避免历史期出现空洞。

### 5.4 搜索

- **入口。** 全站顶栏搜索框回车进入搜索页；筛选状态保存在 URL 里，可分享。
- **索引范围。** 所有已发布期的条目：标题、摘要、来源名、板块名（周刊）。不索引原文全文。
- **英文匹配。** 大小写不敏感；前缀匹配（`kuber` 命中 Kubernetes）；词长 5 以上允许 1 个拼写错误，9 以上允许 2 个。
- **中文匹配。** 无需空格分词，"终端 工具"命中同时含"终端"和"工具"的条目；全部词命中排前，部分命中排后。忽略标点与全半角差异。
- **筛选。** 刊物类型（日刊、周刊）、来源（多选）、日期范围（近 7 天、近 30 天、全部、自定义）。
- **结果。** 标题与摘要片段高亮；显示来源标签、所在期（可点回该期）、原文链接；每页 20 条，默认按相关度。
- **空结果。** 提示放宽筛选或检查拼写；不做推荐（P2）。
- **权限与限流。** 仅登录用户可搜（随 D1-A）；每用户每分钟 60 次。

### 5.5 账号与登录

- **方式。** Google、GitHub 的 OAuth 2.0 授权码流程，带 state，能用 PKCE 则用；只申请基本资料与邮箱（GitHub 需 `user:email` 才能拿到主邮箱）。
- **建账。** 首次登录创建用户：显示名、头像、邮箱。再次登录按 provider 与 provider uid 匹配。
- **合并。** 新登录方式返回的已验证邮箱与现有用户一致，自动绑定为同一用户；邮箱未验证或缺失则新建独立用户，并提示"如已用其他方式登录过，请改用原方式"。
- **会话。** Cookie 会话 30 天，登出即清除；HttpOnly、Secure、SameSite=Lax。
- **角色。** admin 与 member；admin 由环境配置的邮箱白名单决定，MVP 单管理员。
- **未登录。** 访问任意内容页跳登录页；登录页只有产品一句话简介与两个登录按钮。
- **失败处理。** 用户取消授权或回调失败，回到登录页提示重试，不暴露内部错误。

### 5.6 管理后台（最小）

仅 admin 可见：源管理（5.3）、抓取记录、"立即生成今日日刊"按钮、用户列表（只读：登录方式、最近登录时间）。

## 7. 数据与抓取

![数据管道](assets/pipeline.svg)

图 1 · 数据管道。调度器按时触发各源适配器；条目交给期生成器装订成不可变的一期，再写入数据库并建索引。某个源失败只触发告警，不阻塞当期发布。

| 源 | 刊物 | 获取方式 | 频率 | 风险 | 应对 |
|---|---|---|---|---|---|
| Hacker News | 日刊 | 官方 Firebase API（topstories 加 item）；Algolia HN API 可按日期回填 | 每日快照 | 低。免鉴权，长期稳定 | 超时重试 3 次 |
| GitHub Trending | 日刊 | 解析 `github.com/trending?since=daily` 的 HTML | 每日快照 | 中高。无官方 API，结构可能变更，可能限流 | 适配器隔离；解析失败即告警；每日仅抓一次并标注 UA；备选 D4-B |
| Hackaday | 日刊 | RSS：`hackaday.com/feed` | 每日快照，取近 24 小时 | 低 | 处理编码与相对链接 |
| 阮一峰周刊 | 周刊 | GitHub 仓库 `ruanyf/weekly` 的期 Markdown；博客 RSS 作为新期信号 | 每日检查新期 | 中。Markdown 结构随期变化 | 容错解析；失败降级为整期一条；用近 20 期样本做回归测试 |
| 通用 RSS / Atom | 日刊或周刊 | feed 地址 | 随所属刊物 | 低 | 同 Hackaday |

- **去重。** 同一源内按归一化 URL 去重（去 utm 参数、尾斜杠、协议差异）。跨源重复（同一仓库同时出现在 HN 与 Trending）MVP 不合并，各栏照常显示。
- **存储。** 只存标题、链接、摘要（500 字以内）与元数据，不存全文；图片只存地址，不代理不缓存。
- **版权。** 页面标注来源并直链原文；上线前核对各源的转载条款；保留单条下架能力。
- **数据量。** 日刊约 75 条/天，周刊约 50 到 80 条/周，一年约 3 万条，存储与索引压力可忽略。

## 8. 非功能需求

- **性能。** 内容页首屏 1.5 秒内（国内网络）；搜索 p95 延迟 500 ms 内。
- **可靠性。** 日刊按时发布率按月 ≥ 99%；单源失败不阻塞发布；抓取失败重试 3 次，指数退避。
- **安全。** OAuth 带 state，能用 PKCE 则用；CSRF 防护；会话 Cookie HttpOnly、Secure、SameSite=Lax；管理接口服务端鉴权；搜索接口按用户限流。
- **可观测。** 每次抓取有运行记录；失败告警到邮件或 IM webhook；基础访问日志。
- **兼容。** 桌面与移动浏览器响应式；支持最近两个大版本的 Chrome、Safari、Firefox。
- **数据。** 数据库每日备份，保留 7 天；抓取日志保留 30 天。
- **成本。** 单台小型 VPS，或 Serverless 加托管数据库，即可承载。

## 9. 成功指标（上线后 4 周）

| 指标 | 目标 | 说明 |
|---|---|---|
| 站长本人使用天数 | ≥ 24 / 28 天 | 最核心：自己每天愿意打开 |
| 日刊按时发布率 | ≥ 99% | 06:30 前可读 |
| 搜索有结果率 | ≥ 85% | 其中产生点击的搜索占比 ≥ 50% |
| 抓取故障修复时长 | 中位数 < 24 小时 | 从告警到重抓成功 |
| 邀请用户回访 | 3 人中 ≥ 2 人 | 第 2 周仍回访，验证不只自己觉得有用 |

## 10. 里程碑

| 阶段 | 内容 | 验收 | 预估 |
|---|---|---|---|
| P0 抓取与阅读 | 4 个源适配器、日刊与周刊生成、阅读与归档页；固定配置，无登录，先本地或内网跑 | 连续 5 天日刊自动生成；周刊抓到最新一期并正确拆条目 | 约 2 周 |
| P1 搜索 | 索引、搜索页、筛选、高亮 | 50 条真实查询有结果率 ≥ 85% | 约 1 周 |
| P2 账号与配置 | OAuth、角色、管理后台、告警 | 新增一个 RSS 源 3 分钟内完成；故意让一个源失败，收到告警且日刊照常发布 | 约 1 到 2 周 |
| P3 上线 | 响应式与空态、备份、监控、版权核对、邀请首批用户 | 3 名外部用户完成登录并阅读 | 约 1 周 |

按单人业余开发估算，仅供排期参考；阶段编号与功能优先级 P0 到 P2 无关。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| GitHub Trending 页面变更或限流 | 日刊缺一栏 | 适配器隔离、解析失败告警、备选 Search API 近似（D4-B） |
| 阮一峰周刊 Markdown 结构变化 | 拆条目失败 | 容错解析、整期降级、历史样本回归测试 |
| 中文模糊搜索质量不达预期 | G3 落空 | 选原生支持中文分词的搜索引擎；上线前用 50 条真实查询验证并调参 |
| 版权与转载 | 被要求下架 | 只存摘要、直链原文、登录可见、单条下架 |
| 账号误合并 | 他人登录到你的账号 | 只合并 provider 标记为已验证的邮箱 |
| 维护中断导致缺期 | 历史不完整 | 失败可告警可手动补抓；HN 可用 Algolia 按日期回填，GitHub Trending 无法回填，接受缺失 |
