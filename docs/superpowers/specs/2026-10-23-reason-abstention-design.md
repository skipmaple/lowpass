# 推荐理由：资料不足时不写

状态：2026-10-23 产品负责人已确认完整方案，并授权本地实现与离线验收。2026-10-24 完整候选已通过本地离线验收，已建未合并草稿 PR #91，尚未生产启用。

依据代码：main `d233d57990829f4420fd9a26adbef18b88602390`。本设计在独立工作区编写，不改已发布内容、生产提示词、模型配置或调用预算。

## 1. 已确认的方向与本次建议

产品负责人已确认：只有名称、没有可靠说明的条目（例如仅有「Voxtral 3」），证据不足时允许不写推荐理由。原问题明确限定为先确定产品规则，不增加模型调用、不直接改生产。

这项方向服务于「以获奖品质为标尺」中的内容质量：读者不应因为模型熟悉一个名称，就看到输入资料无法支持的功能、价值或兴趣关联。所有来源条目仍完整刊登；这不是减少条数或按相关性筛选。

以下工程与产品细节已随完整方案确认，纳入本地候选实现范围：

- 资料不足是一种合法、可持久记录的处理结果，实际调用仍收费、记账，收到该结果即结束本条重试。
- 新条目不写理由、标签或同次译文；已有条目保留旧理由、标签、译文与时间，另记「本次资料不足，保留旧理由」。旧理由不会被称为通过了新证据验收，也不再向新刊复用。
- 普通补缺不重复处理已记录的资料不足；管理员显式重生成可以重新评估。新的日期创建新条目时重新评估，不跨日复用拒写结论。
- 第一阶段仅实现本地候选并完成离线验证，不执行真实模型试验、不合并部署。新提示词的实网内容验收与生产启用另行确定范围。

本地实现已同步修订 PRD 所列契约，完成结果见实施计划；这不表示生产提示词或数据已改变。

## 2. 怎样判断资料不足

模型只能使用 R-9.2 已有输入：标题、说明、来源、有限元数据与兴趣画像。当前提示词没有提供 URL；试验执行器中存在的网址也不能算模型已知依据。不补抓全文，不引入检索、外部知识库或第二次核验调用。

先判断输入能否支持一条具体、诚实的选读理由，再判断它与画像的关系。

- 只有不透明名称、版本号、仓库路径、stars、得分、评论数或编程语言，不能据此推导具体功能、效果、部署方式或使用场景。模型记得某个产品，不等于这次输入已说明它是什么。
- 标题本身已明确功能、议题或论点时，摘要为空也可以有足够资料。不按摘要有无、字符数、领域关键词命中或名称白名单直接判定。
- 资料足够但相关性低，仍据实写理由并诚实注明相关度；不能把弱相关伪装成资料不足。
- 保留主体、否定、计划/已实现、可能性、应用运行位置/模型推理位置、引用/作者主张的区别。可提出读者能考察的角度，不能把尚未展示的收益、教程内容或实测结果写成已经存在。
- 若不扩写资料、不套通用关联就无法写出完整的 20–60 字理由，选择资料不足；不能为了达到字数填充空话。

解析器校验输出协议和形式，不能自动证明模型的证据判断正确。字符数、领域名出现及合法 JSON 都不代表事实核验通过。

### 既有真实材料的设计边界

继续使用已经冻结的六条真实输入和十组语义对抗卡，不重建案例框架，不把人工预期冒充实网模型结果。

| 材料 | 允许的处理 | 不允许的扩写 |

## 3. 模型输出与解析契约

本地候选提示词要求两种明确分支。首次解析和有限重试均使用相同协议；不在失败后自动放宽验收。

有理由时：

```json
{"decision":"generated","reason":"…","interest_tag":"AI / LLM","summary_zh":"…"}
```

- `decision` 必须是 `generated`；`reason`、`interest_tag` 必须为字符串。
- 理由沿用 D37 的空白归一化和 20–60 个 Unicode 字符验收，不截断；须包含汉字，并点名标签所选的那个启用领域。标签必须精确命中启用领域名，正文领域与标签不能错配。
- `title_zh` / `summary_zh` 仅按条目所需类型接受；维持 D25 现有限长、含汉字、同次成功结果与失败隔离规则。不合规译文不连累合规理由、不单独重试；本次没有新译文时保留旧译文。

资料不足时，完整对象为：

```json
{"decision":"insufficient_evidence"}
```

- 此分支只接受该键值，不接受理由、标签、译文、自由诊断文字或其他附带字段，包括空字符串和 null；矛盾对象仍是 invalid。
- 不保存本次任何生成内容，只持久记录合法判断与时间。
- 缺 `decision`、未知值、非对象、空响应、理由违规等均为 invalid，不能自动改判成资料不足。未配置供应商、预算阻止请求、拒绝、限流、超时也不是资料不足。
- 保留现有兼容 OpenAI 端点的外层 JSON 提取方式；取出对象后的分支校验必须一致。解析异常不能被视为合法终态。

严格判别字段可能使不遵守新协议的模型多产生 invalid，这是实网候选验收需要测量的风险；离线测试不能代替该项。模型、供应商、价格、月上限和现有 max_tokens 预算不在本轮改变范围。

## 4. 独立保存判断，保护历史内容

新增一对一 `ReasonAbstention` / `reason_abstentions`，只记录最后一次合法「资料不足」决定。采用项目既有主键格式与 PostgreSQL 18：

| 字段 | 契约 |
|---|---|
| id | 25 字符 UUIDv7 base36，项目既有主键生成 |
| item_id | 非空、25 字符、数据库唯一索引；外键指向 items，删除时 CASCADE |
| assessed_at | 非空 UTC 时间，该次合法判断完成时间 |
| created_at / updated_at | 独立记录自身的时间，不 touch Item 或 Issue |

不新增自由文本或原模型响应，不保存新的画像、资料快照或模型密钥。判断记录与条目同寿命；不依赖会在 90 天后清理的 ModelCall，不为历史条目回填记录。保留 ModelCall→Item 的既有关系即可追溯保留期内的调用，无需让 marker 依赖账本行。

- 新条目合法拒写：建/更新 marker；Item 的 reason、interest_tag、title_zh、summary_zh、reason_generated_at 与 updated_at 全部保持原值。
- 已有理由手动重生成后合法拒写：也只建/更新 marker。旧内容继续对读者显示；后台明确本次资料不足且保留旧理由。此设计不批准自动撤下或删除历史理由。
- 合法 generated：按原规则保存本次理由、标签、译文和生成时间，并在同一数据库事务内删除旧 marker。
- 生成失败：内容、时间与既有 marker 均保持，真实失败请求仍记账；一次失败不会抹掉上次合法判断。
- marker 的创建/覆盖使用数据库唯一性与受锁保护的持久化；并发写入不产生重复 marker，不得出现新理由已提交而旧 marker 仍在的中间状态。记录最后完成并提交的合法结果；本轮不另建任务调度系统。
- 重抓使用 delete_all 替换旧条目时也由 FK 级联清理 marker；不能仅依赖 Rails destroy 回调。条目下架沿用 visible 过滤，恢复可见后保留它原有判断。

期与源内容不可变的边界保持；新记录只是推荐理由处理元数据，不修改标题、摘要、原文、源顺序、期发布时间或 revised_at。

## 5. 结果、调用次数与费用

`ModelCall.status` 新增 `abstained`（9 字符，现有列长 10 足够），同步模型校验和数据库 CHECK；不把它记作生成成功、技术失败或未调用。使用本次真实 usage、单价、耗时记账，error_summary 留空。

生成入口对调用方明确区分 generated / abstained / failed；整期 Outcome 增加 abstained 数，不复用表示供应商/画像未准备好的 skipped 布尔值。单条控制器和整期流程都须消费这些结果。

- 首次收到合法拒写：一次真实请求、一次 abstained 账本，立即结束本条，不再重试。
- invalid / 超时后重试收到合法拒写：保留之前的真实请求账本，记录此次 abstained 后结束；不能丢掉失败费用，也不能从前次响应带入译文。
- 其他失败仍最多首次加两次重试，每次真实请求前重查月上限；401 / 403 / 429 不追加重试；预算未发出的请求不记账。
- 预算耗尽时按 D37 停止并告警；缺失数按下一节统一定义。最后一条取得合法结果且不需后续请求，不额外制造预算终止事件。
- 调用账本仍保留 90 天，清理后 marker 继续有效。每日调用次数与费用包含 abstained 的真实请求。
- 账本继续反映真实请求，即使随后业务持久化失败也不能把已收费请求抹掉；数据库异常走现有任务失败/错误报告，不作为解析失败额外重试模型。

## 6. 补缺、复用、计数与告警

在 Item 层集中定义待处理理由范围，所有调用处共用：可见日刊条目，reason 为 nil，且不存在 ReasonAbstention。无需新增分钟任务；tick 继续只检查告警，不自动请求模型。

| 操作 | 行为 |
|---|---|
| 正常发布/重抓后的 only_missing 补缺 | 仅处理统一待处理范围；已合法拒写的同条目不再收费 |
| 管理员单条或整期显式重生成 | 重新评估所有被操作的可见日刊条目，仍检查预算；不因 marker 自动跳过 |
| 次日相同 URL 的新条目 | 不复用拒写 marker；正常重新评估；原 R-1.11 成功理由复用仍适用，但候选旧条目必须无 marker |
| 画像/模型设置改变 | 不自动改历史或清 marker；之后的新条目使用新配置，历史仍由管理员显式重生成 |
| 同源重抓 | 新条目重新进入流程；不把旧 item_id 的 marker 迁移到新条目 |

排除带 marker 的旧理由复用是必要的：保留旧内容供历史阅读不等于允许它绕过新判断继续复制。仍保持 D25 对相同原文及合规译文的复用前提。

后台、Generator、预算摘要、Scheduler 和完成判断必须使用同一待处理定义，不能遗留直接 `reason:nil` 的缺失计数。

推荐理由缺失的恢复按 issue 收窄：只恢复这期已有的 reasons_missing 事件，且待处理为 0、月预算未耗尽。不能让一期处理完成关掉别期仍缺理由或预算尚未解除的事件。源抓取、搜索等现有其他告警的恢复语义不改。

本次不新增告警渠道、自动修复请求或常驻进程。

## 7. 读者与管理员看到什么

读者：新条目拒写后，标题、原有说明、元数据、原文与收藏操作完整保留；不显示空标签、假译文、失败占位或逐条诊断。已有理由拒写重生后仍显示历史原内容，不给它新增证据核验标识。

后台期列表沿用现有表格、字体、令牌和展开区，不改版、不引入新颜色或装饰。理由格给出互斥的四类可见条目计数，合计为本期可见日刊条目数：

| 类别 | 定义 | 文案 |
|---|---|---|
| 有理由 | reason 非空，无 marker | 已有理由 N 条 |
| 无理由且已判断不足 | reason 为空，有 marker | 资料不足未写 M 条 |
| 保留历史理由且本次不足 | reason 非空，有 marker | 保留旧理由 L 条（本次资料不足） |
| 尚待处理/失败未解决 | reason 为空，无 marker | 缺 K 条 |

零值可省略；不足判断的时间在既有「刊物详情」展开区显示为最后处理时间，不冒充 reason_generated_at。未配置供应商/画像时保留现有不可生成事实与按钮禁用原因，但已有处理计数仍按真实数据计算。待处理筛选只因 K>0 或其他已有故障命中，不把合法拒写当故障。

单条重生成：generated 沿用「已重生成」；新条目拒写为「资料不足，未生成理由」；有旧理由拒写为「本次资料不足，保留旧理由」；真实失败仍显示失败事实。管理员写操作按现有审计路径记录实际结果，不写入收藏或私密材料。整期异步操作的提交提示仍只说明任务已开始，完成状态由期列表真实计数呈现，不把拒写计入「已生成」。

## 8. 实现后的离线验收

仅使用 fixtures、Provider stub、既有六条真实材料的私密人工检查与十组语义卡；自动测试不连网络。新的测试必须覆盖行为差异，而非只镜像方法结构。

| 编号 | 必须证明的结果 |
|---|---|
| A1 | 两分支合法解析；缺/未知 decision、混合分支、空对象等 invalid；generated 保留 19/20/60/61 字边界并拒绝领域错配、非中文理由 |
| A2 | 合法拒写一次调用一次收费账本，零额外重试；invalid→拒写为两次真实账本且不串用译文；月上限、零上限、401/403/429、超时与三次失败原门禁保持 |
| A3 | 新条目拒写不改任何 Item 字段或 updated_at；已有理由拒写保留所有旧字段；失败保留旧 marker；成功写入与删 marker 原子完成 |
| A4 | 普通补缺重复执行零新增请求；显式单条/整期重生重新评估；ModelCall 清理到 90 天后 marker 仍生效 |
| A5 | 互斥四类计数总和正确，隐藏条目不计，待处理筛选准确；资料不足不是「已生成」或「未配置」 |
| A6 | 分钟检查和预算摘要排除合法拒写；本期完成只恢复本期事件，其他期与未解除预算事件不误恢复 |
| A7 | 跨日不复用 marker，带 marker 的历史理由不再向新条目传播；原成功理由/同原文译文复用保持；重抓 delete_all 级联清理 |
| A8 | 读者无空标签/拒写诊断，收藏与原文不受影响；后台新状态键盘可达，375/390px 与桌面无溢出，减少动效设置保持 |
| A9 | 六条资料的判断范围与十组正反卡经独立内容审查；明确这不是模型稳定通过或事实已经核验的证据 |
| A10 | 独立 diff 审查、相关 Rails/前端测试、完整 bin/ci 与 300 KB 首屏门禁均通过；不生成 PDF 验收，网页状态用实际浏览器验收 |

后续若申请有限实网试验，沿用已冻结输入与现有执行器，重新写明次数、预算、模型、零/有限重试、记账副作用和停止线，取得新授权后才发请求。之前的 12 次试验额度已用完；本设计不追加额度。内容验收须同时观察误写与无必要拒写，不能靠大量拒写抬高表面合规率。
