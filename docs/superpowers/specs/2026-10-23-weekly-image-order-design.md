# 周刊配图恢复原文段落顺序

状态：既有品质目标、D24 完整正文与 D36 既有配图范围内的工程修正候选；设计已独立审查，代码与实际页面验收中，不代表合并或部署授权。

## 问题与依据

真实样本 `test/fixtures/files/ruanyf/issue-393.md:61–65` 的顺序是介绍耳机、配图、“上图中”的说明。当前解析器从正文删除图片，另存去重后的 `meta.image_urls`；`ItemRow` 再把全部图片放在全文后。手机截图中说明在图上方，失去了原文的指代关系。专题的段中图片也有同样问题（该样本第 16–20 行）。

PRD 7.2 已有源特定 JSON `meta`，不需要新增 Entry 顶层字段或数据库列；D24/7.5 要求完整纯文本正文，并未要求配图统一置后。本方案保留现有全文、摘要、链接、图片集合及展示令牌，只补足尚未丢失的原文位置。PRD 7.3 未列出现有 `image_urls`，5.2/7.9/D9 的“不展示”仍与 D36 明示的既有周刊展示冲突；同步说明这一已有例外，不能扩展到日刊或通用 RSS。

## 兼容契约

- 新增可选 `meta.image_positions: number[]`，与现有已解析成绝对地址、去重后的 `image_urls` 严格一一对应。
- 数字是**最终清洗后 content 的段落边界**：0 表示第一段之前，N 表示 N 段之后。同一边界的图片保持 URL 顺序并使用既有多图版式。数组须为单调不减的整数，范围 0..N。
- 仅在一次新的正常抓取/获准的管理员重抓中随新条目生成。无历史回填、发布后补写、缓存旁路、数据库迁移或新网络请求。
- 旧条目无位置、位置无效或映射不能完整证明时，整条保留现有“全文后图片”展示；不部分重排、不丢正文或配图。
- 后端位置推导最多处理每条 128 张现有图片；超过时只省略新位置字段，不减少原图片。该上限是工程资源保护，不是新的展示限制。

## 位置如何证明

解析器保留一个仅在内存使用的 `image_body`，仍沿用原有标题判断和正文剥离规则；持久化 `summary/content` 的输入不变。

适配器的位置助手使用既有 SummaryCleaner：其 content 参数是 `SummaryCleaner.content(item[:summary])` 的最终值；Entry 仍接收原始 `item[:summary]`，不能把清洗后正文再次写入 Entry（清洗不保证幂等）。删除 image_body 中图片后，整体清洗结果必须与该最终值逐字相等。每张独占一行的图片之前，前缀清洗所得段落必须与最终正文的对应前缀完全相等，才得到段落边界。

下列任一情形整条不生成位置：行内图、重复图片地址、代码上下文中的图片语法、地址解析失败或解析后碰撞、图片/位置数量不一致、清洗跨边界导致前缀不一致、无正文、完整正文达到 50000 字安全上限（无法证明未截断）。重复图须重新扫描 image_body 未去重的出现序列，不能依赖已经 uniq 的 image_urls。图片行有 tab 或至少 4 列前导缩进、处于反引号代码片段或 tilde 围栏内时不定位；出现 HTML pre/code 元素、HTML 注释（包括未闭合）或标签属性中含图片语法时保守地整条回退。普通不含图片的行内代码不一律拒绝。不给普通文字塞占位符，不按“上图/下图”猜图，不按译文推位置。

## 前端

将现有周刊正文与 WeeklyMedia 放入一个 `WeeklyContent` 组件，日刊、标题、推荐理由和收藏行为保持原路径。新位置必须全部合法，且存在原 content，才按段落边界穿插现有 WeeklyMedia。旧记录继续走旧 DOM 结构。

保留天然宽高、比例占位、懒加载、解码、referrerPolicy、错误收起和全条目图片编号；每个 URL 最多显示一次。沿用 `.item-content--weekly`、`.item-media` 与既有字体/颜色/字号。只补图片之后正文的既有段间距，不添加图注、边框或新交互。
