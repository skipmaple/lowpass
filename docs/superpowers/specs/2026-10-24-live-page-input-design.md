# M2：可直接操作的新页与旧页方向退出（待批准的本地候选设计）

状态：提案，未批准、未实现。日期 2026-10-24。基线 origin/main d233d57990829f4420fd9a26adbef18b88602390。
本说明批准后仅进入本地实现、离线回归与自然播放验收；不包含合并、部署、生产写入或收费模型试验。

## 意图与明确的产品取舍

读者不应为了 240/360ms 的视觉反馈而错过账户、搜索输入、书签、链接或原生拖动取消。当前浏览器把新页一起捕获，播放期间点击落到 HTML；已实测“中断后捕获指针”的补救会丢失输入焦点，并让拖出取消变成按钮激活。

建议调整 D34/M2 的一项可见契约：**新页固定在最终坐标，只淡入；旧页仍按前/后方向横向退出 24px 并淡出。** 普通跨页跳转仍为 240ms，前/后一期仍为 360ms，继续使用现有缓动。报头保持静止；期头旧日期与新日期在新页期头位置交替。日期随本次换页采用相同总时长，方向性翻页为 360ms。

用户开始鼠标、触摸、笔、键盘或滚轮操作时，立即完成正在播放的反馈，原始事件继续由新页正常处理。没有额外点击、播放按钮、滚动接管或事件重放。
这两项是工程建议，尚未当作用户已同意的决定；现有“新页从左/右滑入”不能悄悄替换。

## 保留的约束

沿用 Inertia/React、浏览器原生 View Transitions、CSS/WAAPI 以及现有令牌，不引入动画库或克隆双 DOM。
旧正文仍由浏览器捕获 root 视口，避免长文档边框替代视口而产生空纸退场。
纸色、纹理、版宽、文字、导航、已发布刊期、图片 URL 与加载规则保持现有数据契约。周刊白底图片在整个播放期间仍为纸色，不能以 CI 通过代替画面验收。
不保存/代理/改写原图，不新增 HTTP 探测。减少动态效果与不支持 API 的浏览器仍直接切换。
本地验收不能充当物理手机、生产或获奖证明。

## 方案结构

### 1. OLD 捕获，NEW 退出所有命名捕获

track 回调仍在旧页捕获前设置本次 token/方向。OLD 保留 root、masthead、issue-date 的原生命名关系：root 是完整视口，另两个部位从 root 中分离。

React 新页提交期间同步切换 NEW phase：root、masthead、issue-date 的 NEW 名称全部为 none。没有 NEW 捕获祖先包住输入或控件。原生过渡伪元素不参与命中；它们只画 OLD。

若新页有报头，OLD masthead 图立即隐藏，露出正常的新报头。若新页为无报头登录页，OLD masthead 采用同次淡出，结束后消失。不能靠普通菜单提高 z-index 穿越 native overlay。

新页正文只做 opacity，从 0 到 1，不做 transform。账户、表单、链接和文字选择的 DOM 坐标从提交后至结束保持固定。旧 root 继续按方向移动 24px 淡出；没有方向时只淡出。旧日期单独淡出，不跟随 root 横移。

### 2. 以 React 提交作为 pre-NEW 入口

不能用 updateCallbackDone.then 切 phase：其 reaction 在 Blink 中可能已经晚于 NEW 名单采集。也不单靠 navigate：replace 分支不会发该事件。

设计采用两个显式同步提交探针：共享 Layout 与唯一跳过 Layout 的 Login/Show，均读取 usePage 并在 useLayoutEffect 中通知过渡模块。当前 16 个页面中，其余 15 个通过 Layout（含 AdminLayout）；本地回归必须验证覆盖清单，今后新增无 Layout 的页面也须接入。

router.beforeUpdate 仅记录服务端 GET 将提交的目标 Page 对象，不在这里改变 CSS phase；该事件发生得太早。track 把本次目标对象与 token 绑定。提交探针只接受与本次目标 Page **相同对象**的提交，不用“URL 相同”或“对象有变化”替代，以免 flash 等非导航更新提前放行。

Inertia 3.7.0 源码表明 response beforeUpdate.detail.page 经 page.set/swap 到 React PageContext 仍为同一对象，服务端 replace 也走此链。实现前针对锁定版本写出覆盖断言；StrictMode 重复 effect 必须幂等。

跨路由的 DailyLayout/WeeklyLayout 等祖先类型不同，可能使内部 Layout 卸载重挂；不能依赖“Layout 始终持久”。提交探针必须在首次挂载也处理匹配 Page，unmount/StrictMode cleanup 不可无条件删除全局 token 或 NEW phase。flash 的克隆 Page 不能作为目标提交；若导致身份未匹配，则按未匹配的收尾策略处理，不降级为 URL 匹配。

本候选只对现有符合条件的服务端整页 GET 启用。现有保留状态、异步、预取、局部刷新、表单、同路径访问继续不启用自动过渡。router.push/replace 的客户端访问不发 beforeUpdate，不在此设计中偷偷以晚到的 clientVisit 补入口；若本地审计发现产品正在为此类访问显式启用 VT，应先明确收窄入口或修订设计，不能宣称已覆盖。

找不到匹配提交时，以终态结束本次反馈，不能把错误 Page 作为 NEW。重叠、跳过、拒绝时旧 token 不可清掉新 token；保留现有后退等待换页与阅读位置恢复机制。

### 3. 播放、纸面和日期

NEW phase 切换在提交探针内同步完成。等 native ready 后启动 NEW 正文淡入；它要以同次 native 动画的实际时间轴对齐，不能另等 timer/rAF 延迟来掩盖不一致。实现中先读取实际 native 时钟并采用同一 timeline/startTime；若 API 不能可靠对齐，应停止并修订方案，不能以两个差不多的时钟通过。

opacity 会建立混合组，因此播放期间给 .sheet-body 自身临时提供既有 paper 颜色/两层纹理。背景位置按外层 paper 与正文两者边框 rect 差对齐，保持与未过渡纸面相同的纹理相位；尺寸/布局不改变。临时纸底必须在淡入之前就位，结束后移除。登录页已有自己的 paper，并对其现有整页容器应用相同淡入规则。不得把背景从 body 外移走而造成打印/正常态变化。

新日期仍为普通 DOM，参与正文原位淡入。ready 时在 Inertia 滚动重置之后读取新日期的视口位置，将 OLD issue-date group 放在这个位置淡出；尺寸保留 OLD 内容自身尺寸，避免拉伸旧字。无新日期时旧日期只在原有可见位置淡出。分组定位须在首个实际播放画面前生效；不能证明时序或画面有飞掠即失败。

自然播放必须包含长→短、短→长、页脚翻页、上一期/下一期、不同日期宽度、手机/桌面、登录重定向。旧图在原视口所见的内容要保持；不得把 blank-paper 差异解释为修复。

### 4. 输入优先的收尾

ready→finished 时，用 document capture 监听可信 pointerdown、keydown 与 wheel，在默认动作前同步结束 OLD 原生过渡，并把 NEW opacity 置为终态。监听器不 preventDefault、不 stopPropagation、不调用控件 click/focus、不合成事件、不设置 pointer capture、不改变滚动策略。

因为 NEW 没有位移，pointerdown 的目标及同一手势随后 pointerup 的几何不会被收尾移动。输入焦点、光标落点、拖选、按住拖出、触摸 pan/cancel 与修饰键链接应由原生默认动作完成。自动的 navigation focus 与程序触发事件不能被当成人工操作而提前终止动画。

输入作用于已提交的新页；旧图仅是反馈，操作时立即消失。跨页内容仍有短暂交叠，这是淡入淡出的可见取舍，不保证旧图中的链接在新页有相同语义。验收须包括快速点击新页不同位置，防止误点被“按钮打开了”掩盖。

capture/update 阶段的浏览器渲染暂停早于 ready，不包含在“播放期间可操作”的承诺中；要单列观察，不可用暂停动画的测试声称没有该限制。重叠访问/后退的原有保护不可删除。

先保留现有 baseline，写失败回归，再实现最小候选；独立审查最终 diff。只对这次改变运行有意义的测试，完整 bin/ci 通过后继续实际浏览器验收。

1. 当前真应用固定案例：375/1440、普通/减少动态效果；账户打开/焦点/Escape，搜索点击指定光标并输入，按住按钮拖出无激活，正文链接/修饰键链接、收藏反馈、原生滚轮。原生事件必须可信，记录实际目标和默认结果。
2. 真实触摸输入机制案例单列：按钮 tap、输入聚焦/输入、pan→pointercancel 不激活；模拟器不能被称为物理设备结果。
3. 自然 240/360ms 播放前/中/后画面与时间证据，不暂停、延长或改变速率。白/黑合成 SVG 与既有真实图片分别检查纸面；合成图不替代真实周刊检查。
4. 两个方向、长短页与页脚几何；报头静止，日期在新期头位置交替；无闪白、空纸回退、文字拉伸、菜单/弹层遮挡、横向溢出、终态残留。
