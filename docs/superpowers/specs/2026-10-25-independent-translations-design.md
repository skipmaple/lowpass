# 日刊缺译文独立补全

日期：2026-10-25。状态：完整设计已于2026-10-25获用户批准；进入本地实现与离线验收，尚未完成实现或部署。

本文以本地组合候选 `734c78cb7162d2a1943df5e90b6774edf3fd2508` 为设计基线，包含尚未发布的 D38 理由拒写契约。生产诊断取自 main `1e2a04eb3ad6b7f668b8e0f64bd123d8ad783004`，不能将本地契约当成生产现状。第一阶段只做本地设计；后续本地实现、离线验收、实网试验与发布分别记录状态。

## 1. 要解决的问题与已确认边界

用户发现日刊英文标题下缺少中文译文。2026-10-25 的 HN 10 条中，7 条数据库与页面 props 的 `title_zh` 均为空，既有调用出现超时或理由验收失败；不是已有译文被 CSS 隐藏。真实主干解析器先验理由，再接受译文；失败整次不保存，缺译文又没有独立补全入口。历史原始回复未保存，不能恢复其中可能存在的译文。

用户已明确选择：

- 没有推荐理由，也可单独翻译。
- 失败响应中的译文仍不保存。
- 每次补全检查现有月费用上限并记账。
- 历史补全必须显式启动。
- 下一步先做完整本地方案，不发起真实模型请求或部署。

下面的协议、自动触发顺序、重试上限、保留原文状态、后台入口与并发方式是工程建议，属于待确认的完整设计，不冒充用户逐项指定的实现。

目标是让“理由结果”与“中文阅读辅助是否补齐”成为两个独立判断。保留原文、全量刊登、既有视觉语言、D37 失败隔离与 D38 合法拒写。翻译只能表达给定文本，不增加产品功能、解释、立场或事实核验结论。

不扩展周刊翻译、文章全文翻译、摘要生成、抓取原文、检索、第二供应商、本地模型、常驻进程或自动历史回填。不把补全失败、未配置模型或预算不足做成读者页诊断、空占位或发布阻塞。

## 2. 三种路线与采用的路线

| 路线 | 结果 | 选择 |
|---|---|---|
| 放宽理由验收或从失败响应捡译文 | 仍解决不了超时；改变 D37 隔离与 D38 严格拒写 | 不采用 |
| 每个条目一律分开请求理由和翻译 | 彼此独立，但连已成功附带译文的条目也新增调用 | 不采用 |
| 保留同次成功附带的译文，缺失部分独立补全 | 不重做已有合规内容；无理由的条目也能补中文 | 采用 |

这改变 D25 / R-9.10 的“只搭同次理由调用、不增加独立调用”；不改变 D37 的“失败同次译文不保存”。D38 的拒写对象仍只能是 `{"decision":"insufficient_evidence"}`，拒写调用不写 Item；另一次合法翻译调用可以独立更新译文字段。拟以 D39 同步这个狭义的发布后补写例外。

## 3. 哪些内容需要翻译

只处理已发布日刊的可见条目，资格集中在 Item 的同一查询/API，供自动任务、后台计数和补全操作共用：

- HN 与日刊 RSS：沿用 `translate_title?`，只译无汉字的标题，目标 `title_zh`，最多 300 个 Unicode 字符。
- GitHub Trending：沿用 `translate_summary?`，只译非空且无汉字的简介，目标 `summary_zh`，最多 500 个 Unicode 字符。
- 周刊、隐藏条目、未发布条目、中文原文、空简介均不请求模型，也不计待补。

同一期每条目当前最多需要一个字段。资格仍由源的既有适配器类型决定，不依赖兴趣画像、不依赖 reason 是否为空、不依赖 ReasonAbstention 是否存在。

合规的既有非空译文视为完成，独立补全不覆盖。对已有译文不做数据迁移或全库重验。独立补全本身也不“修正”历史译文；既有显式理由重生成成功后附带更新译文的行为维持原契约。

### 保留原文不是失败

例如 `Dream-1`、`FreeDNS`，仅有名称或标识时允许模型合法判断“保留原文”，不强造一行带汉字的解释。英文句子仍应翻译；不得用“资料不足写理由”来决定不翻译。名称判断由翻译协议承担，不按字符数、关键词或名称白名单在本地一刀切。

合法保留原文有持久标记，普通补缺不反复收费。后台可显式重新评估这些条目；默认补全不包含它们。语法校验不能证明“应否保留原文”或译文忠实，必须以冻结样本与后续获授权的实网内容验收覆盖，不能将 JSON 合规当成翻译质量已过。

## 4. 自动与手动触发

### 自动：只随新内容走

正常新日刊发布：冻结本次新刊可见条目 id 集合，随发布后既有理由任务传递。理由阶段结束后，对该集合中的缺译文补全；合规理由已附带译文的直接跳过。理由普通失败或合法拒写均可进入翻译阶段。

自动范围以入队时上海日期冻结：只有期日期等于当日的本次新发布/重抓才附带翻译目标。过去日期的补生成、重抓即使创建了新 Item，也不自动追加独立翻译，仍需下面的显式补全入口；旧理由流程原有行为不变。任务晚于午夜执行，不扩大或缩小已经冻结的当日目标。

管理员重抓某源：只传入本次实际插入的新条目 id，不能稍后按来源查询所有行来代替，也不顺手补其他来源的历史缺译文。需要让内部装订返回本次写入 id 与既有 dropped_count；源适配器的条目契约不变，周刊追加/替换行为不变。

若理由阶段遇到 401/403、429 或预算耗尽，本次操作停止后续模型请求，不紧接着用翻译流程再试一遍。任务返回明确的停止原因给外层，不能只返回 failed 数量。只有画像为空但供应商可用时，理由阶段跳过、翻译阶段仍可执行。

迁移、启动、读者访问、普通刷新、搜索、收藏、分钟 tick、旧队列任务默认参数和后台“重生成理由”均不自行启动历史翻译。旧队列消息没有冻结的翻译 id 集合时，翻译阶段为空。部署日不扫旧刊。

### 手动：指定一期，只补缺失

后台为已发布日刊增加 CRUD 资源 `POST /admin/issues/:period_key/translations`，异步提交，受现有 admin、CSRF 与审计保护。周刊、未发布/空刊拒绝，非管理员 403。

该入口冻结当时这一期的待补 id，不重抓源、不重生成理由、不覆盖已有译文。一个默认关闭选项“重新评估保留原文的条目”允许本次再判断合法保留原文的项；即便打开，也不覆盖已有译文。提交后新出现的条目不混入本次操作。

打开确认时，通过只读 `GET /admin/issues/:period_key/translations/new` 获取服务端签名的目标预览。预览冻结当前管理员、指定期、所选重新评估选项、目标 `(item_id, field, input_digest)`、操作键和原始签发时间；不保存原文或调用模型。切换选项重新取得对应预览，加载时不能确认。确认 POST 仅提交这份凭据，服务器验证身份/期/选项/时效，按其冻结目标入队，不重新查询并扩大范围。客户端修改 id、digest 或选项会验签失败。任务前再核对当前资格与 fingerprint，只能排除失效目标。

普通重试同一份提交使用同一个操作键；页面上的提交按钮在请求期间禁用。重复提交同一凭据可重复入队，但不增加该键的调用次数上限；再次主动开始新操作才取得新键和新尝试额度。不增加持久化批次表，目标快照随签名凭据和队列消息保留，真实调用的操作键与输入摘要进入账本。

操作键连同原始签发时间一起冻结，任务有效期 7 天，不随重排队或重放刷新；到期不再请求模型，标明过期并交由显式新操作处理。手动提交凭据另有 15 分钟有效期，提交成功不缩短已经入队任务的 7 天期限。这样 90 天账本清理后，旧任务也不能因为查不到旧调用而再次收费。旧理由队列消息的兼容路径不被当成新翻译授权。

## 5. 独立翻译协议

复用当前 OpenAI 兼容供应商、模型、密钥、单价与月上限，不改后台配置。翻译就绪只看 `Reasons::Provider.configured?`，不要求兴趣画像。

独立 Prompt 只发送待翻译的那一个原文字段及其类型，不发送兴趣画像、用户资料、URL、热度或自行补抓的内容。原文用明确数据边界包住，按不可信资料处理。要求简体中文、忠实且简洁、不加解释，保留名称、人名、代码标识和 Show HN / Ask HN 前缀；否定、计划/已经、可能、引用/作者主张不得改变。

合法响应只有两种，必须是一个完整 JSON 对象，独立翻译不沿用“从回复中抠第一个对象”的兼容逻辑：

```json
{"decision":"translated","text":"科技行业以外尚未显现 AI 回报的迹象"}
```

```json
{"decision":"unchanged"}
```

`translated` 只允许 decision/text 两键，text 必须为字符串；去首尾空白、合并连续空白后非空、含汉字且不超过目标字段限长，不截断。`unchanged` 只允许 decision 一键，不能带译文、null、空值或说明。未知 decision、非对象、夹带理由/标签/额外键、代码围栏、非 JSON、超长或无汉字译文均判 invalid；不是合法保留原文。

沿用响应体 64 KiB 上限。翻译输出上限：标题 320 token、简介 600 token，分别等于现有“理由基础额度 + 该类译文额度”，不无限扩充；未来内容验收如证实不足再单独调整。超时按现有 R-9.8 的单次 20 秒约束实现并验证：当前 open_timeout=5 / read_timeout=20 本身不能证明全程 20 秒，候选必须有整个请求的截止时间，不能把网络参数当成总耗时证明。

## 6. 保存、复用与数据模型

成功 translated 只写对应 `title_zh` 或 `summary_zh` 与 Item 的正常 updated_at；不改原文 title/summary/content、reason、interest_tag、reason_generated_at、ReasonAbstention、Issue 的发布时间/修订时间或 updated_at。

unchanged 只写独立标记，不 touch Item 或 Issue。失败不写译文、标记或内容时间；已有字段保持。网络调用与真实账本记录不在业务事务内；业务持久化失败不能触发新模型请求，已发生的调用仍留账。模型有合法输出但保存失败时，该操作键下终止该条；另一次显式操作才能重试保存所需的生成，不从账本重放原回复。

新增 `TranslationPreservation`：一行表示某条目某字段已合法决定保留原文。字段及约束：

| 字段 | 约束 |
|---|---|
| id / item_id | UUIDv7 的 25 字符 base36；item_id 非空、外键 ON DELETE CASCADE |
| field | string(7)，非空，CHECK 仅 title / summary |
| input_digest | string(64)，非空，CHECK 为 64 位小写十六进制 SHA-256 |
| assessed_at / created_at / updated_at | 非空 UTC |
| 唯一性 | 数据库唯一 `(item_id, field)` |

input_digest 由版本化、无歧义的 JSON 数组计算，包含 item 原所属期类型、source_id、源 adapter/publication、字段类型与原文字节；精确原文一致才算同一判断。不存原回复、解释或自由文本。

自动入队与手动预览都冻结上述 fingerprint；在共享请求门内重新读取资格、原文与已存译文，保存时再以 Item 行锁核对相同 fingerprint。条目被替换/删除、隐藏、源类型变动或原文改变时，调用前发现就跳过，调用后发现则丢弃输出，不把旧输出套到新行；已经发出的请求仍记账，不自动跟随新内容再请求。

普通补全跳过当前 fingerprint 的保留标记。显式重新评估仍保留旧标记到新合法结果落地：失败不能抹掉旧判断；新 translated 写译文并删除该字段标记，新 unchanged 更新标记时间。过期 fingerprint 的标记不算终态，后续确有授权的补全可处理，不据此自动发起请求。

跨日可优先复用更早已发布日刊的同来源、同 url_hash、同字段且原文完全一致的合规译文，或 fingerprint 对应的合法保留原文结论。复用不要求旧 reason 存在，也不排除旧 ReasonAbstention；这是译文与理由解耦的必要部分。只从可见条目取值，不跨源、跨字段、跨原文。复用只写新条目的译文/标记，不向旧刊回写，不新增 ModelCall。

## 7. 请求上限、账本与并发

单次操作每个待补字段首次加最多两次重试，总计最多 3 次翻译请求。超时、普通供应商错误和 invalid 可重试；401/403、429 不追加重试并停止本操作其余请求。预算到达上限同样停止。合法 translated 或 unchanged 立即结束。Job 不因为普通生成失败再次自动跑满三次。

新刊中最坏可能有 3 次理由请求加 3 次翻译请求，共 6 次/条；这不是原来 3 次的免费替代。已成功附带译文或可复用内容不增加翻译调用。不承诺每条都一定有中文：供应商、预算、超时、合规性或合法保留原文仍有事实边界。

ModelCall 增加以下字段；字符串必须同步 PRD 7.2 与数据库 CHECK，索引用于查询重放额度：

| 字段 | 约束与用途 |
|---|---|
| purpose | string(11)，非空，默认 reason，CHECK reason / translation；历史行归 reason |
| operation_key | string(36)，新请求必填；逻辑操作键，不是主键，可使用持久化的 Active Job UUID；迁移前历史行允许 null |
| input_field | string(7)，translation 必填且为 title / summary；reason 可空 |
| input_digest | string(64)，translation 必填且为上述 fingerprint；reason 可空 |

不存 Prompt、原回复、密钥、个人信息或价格配置原文。翻译合法两分支均记 status=ok；invalid、failed、timed_out 沿用既有状态，拒写 abstained 仍只表示理由资料不足。usage 已知时包括 invalid 都按实际 token 记估算费用；超时/连接失败拿不到 usage 时沿用未知用量边界，不能把本地记零说成供应商一定不收费。

每次真实请求前在共享的模型请求门内重查月额度，理由与翻译都使用同一 `Reasons::Budget` 总账。门使用跨进程的 PostgreSQL session advisory lock；稳定命名/键，ensure 释放，不在网络期间持有数据库行事务。检查预算、冻结模型/价格配置、检查本操作对当前条目的既有调用、请求、写账和短业务提交必须处在同一临界区，防止多个作业同时读到旧余额或同时补同一字段。没有拿到门时只允许不发请求的排队/重排队，不悄悄跳过目标或产生一次新的操作键。

锁顺序固定为共享 advisory lock 在先、保存时短 Item 行锁在后；拿门之前不得已持有 Item/Issue 行锁，网络期间不得持有行事务。普通查看、抓取发布和不同来源写入不获取模型请求门，避免模型延迟阻塞刊期发布。

同 operation_key/purpose/item/field 的已有成功调用即终态，即使后续保存失败也不能再收费；否则最多三次。额度查询用 ModelCall，不依赖易失缓存；重复入队与作业重放沿用原键。不同目的的三次额度独立，预算总额共用。既有理由请求路径也必须经过共享门；显式同步单条理由操作生成一次固定键，不能每次重试换键。

月上限仍是请求前估算停止线：最后一笔可跨线，未知 usage、进程在请求后/落账前崩溃等不能保证与供应商账单完全相等。本设计不承诺网络请求 exactly-once，也不以通用网络/数据库异常重放整次模型操作。账本或业务写入异常上抛到现有错误报告和队列面板，由显式人工操作处理。

所有理由专属的“最后错误”、成功/失败/拒写计数按 purpose=reason 查询，避免翻译记录覆盖单条理由失败提示。后台模型总次数/费用仍包含两类；额外展示理由/翻译调用数分项，金额均保留现有币种与估算口径。不改变模型、端点、单价、上限或零上限语义。

## 8. 阅读与后台反馈

读者页沿用既有 Translation / Mixed 的字号、字体、位置与纯文本转义；不新增装饰、加载占位、理由诊断、自动刷新或新动效。刷新后显示已补齐译文；保留原文只显示原文。理由缺失不妨碍译文显示。

搜索仍按原文索引，不把译文纳入可搜字段；展示可读取当前 Item 的译文。收藏快照保持不变：只在当前条目的原 title/summary 分别与收藏快照一致时使用对应的后补译文，否则保留快照译文，防止重抓同链接后将新标题译文配给旧标题。标题、简介分别核对，不因一个相同就混用另一个。

后台刊物管理沿用现有表格，不加新列或新视觉体系。在现有理由信息组内追加真实“缺译文 N 条”“保留原文 N 条”，并增加“补齐译文”动作。待处理筛选纳入缺译文，不把合法保留原文当故障。字段资格、计数与实际任务共用同一模型 API，批量查数，不能 N+1。

提交确认明确“只补本期缺译文，可能产生额外模型费用，受现有月上限约束”，并提供默认关闭的重新评估选项。未配置供应商或预算耗尽时禁用并说明事实；待补与可重新评估两类数量都为零才禁用主入口。确认按钮按当前选项计算目标数，零目标不能提交；画像为空不禁用翻译。异步提交只提示“已提交译文补全任务，刷新查看结果”，不把排队成功说成补齐成功。

管理员提交记 `issue.complete_translations` 审计，含期、操作键、冻结目标数和重新评估选项；不含原回复/Prompt。自动路径记录系统完成摘要，个人身份不从网页会话隐式带入 Job。不新增通知渠道或“缺译文”告警种类；现有错误报告、队列面板、后台计数足以支持本轮，理由告警的待处理定义与恢复条件维持 D38。

## 9. 同步点与交付顺序
