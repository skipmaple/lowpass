目标是恢复能够严格对齐的旧刊图文阅读次序，同时保留刊期和条目数据。超出可证明范围的条目继续原样展示。原有产品规则禁止历史位置补写或缓存旁路；产品负责人已批准 D40 的有边界候选和第 416 期发布。

## 推荐方案

在仓库维护一个仅供服务端读取、随代码审查与部署的**静态展示索引**。初始候选只含 2026-W43 第 416 期经完整核对的条目；生成器与复核流程应可用于其他历史阮一峰刊期，后续按已授权范围逐期扩展，不推断其覆盖率。

- 每期一个 JSON 文件，顶层对象固定为 `{version, period, issue_no, source_commit, source_sha256, entries}`；`entries` 是数组，每条为 `{lookup_sha256, rank, identity_sha256, positions}`。后续期刊通过新增文件扩展；同一文件或不同文件出现重复查找键时视为索引整体有歧义。查找键为 `SHA-256(JSON.generate([Issue.id, Source.id, 原刊期号, rank]))`；索引不存原始数据库 ID、正文、图片、原图 URL、用户收藏或用户数据。
- 页面组装周刊数据时，只对已发布、阮一峰来源、已有 `content` 且 **`meta` 中完全不存在 `image_positions` 键**的条目查找索引。显式 `null`、空数组或其他无效值也算键已存在，不得覆盖。使用当前条目重新计算身份指纹：期键、来源类型、原刊期号、`Issue.id`、`Source.id`、`Item.id`、排序、标题、链接、板块、完整正文摘要、图片 URL 序列摘要；与索引不完全一致时不应用。
- 身份序列依次为 `[period_key, "ruanyf_weekly", issue_no, issue_id, source_id, item_id, rank, title, url, section, content_sha256, images_sha256]`，采用版本 1 的 UTF-8 JSON 数组，以 Ruby `JSON.generate` 的明确顺序编码并 SHA-256；完整正文与图片 URL 数组分别先做 SHA-256。不能将 `nil` 与空字符串等同，不能排序或去重图片 URL 后再比较。指纹只用于判断对应关系，不能证明位置本身正确；位置仍须从锁定上游文件生成并经审阅。
- 位置必须整数、数量与原图片序列一致、范围为 0..正文段落数且非递减；原图 URL 必须全为合法 HTTP(S)、无重复，条目内容须未触及 50000 字安全上限，图片数量不超过既有 128 上限。缺字段、重复索引键、非法格式、失配或歧义时整条回退原展示。已有新刊位置始终优先，包含非法位置时也不由索引覆盖。
- 在返回给周刊阅读页的临时 props 副本中附加位置，复用现有 `WeeklyContent` 的全部校验、图片加载、尺寸占位与失败处理；不修改 `Item.meta`、`Item.content`、期、`revised_at`、搜索索引或收藏快照。无需新表、数据迁移、常驻任务、线上原文请求、模型调用，也不复制、代理或处理原图。
- 读取索引时，文件缺失、JSON 无效、版本不支持或重复键均不得造成页面 500；放弃整份有歧义的索引，按原展示回退并记录不包含正文和 URL 的受控诊断。正文段落按 JavaScript `split('\n')` 的语义计算，包括末尾空段；长度按 UTF-16 代码单元与前端 `string.length` 对齐。空段、末尾换行、emoji 或前后端规则不一致时安全回退，不以 Ruby 字符数冒充浏览器长度。
- 管理员重抓、条目更换、正文、URL、标题、排序或板块改变时，身份指纹不再匹配，自动退回当前展示。只改变源文件中的图文位置却不改变正文与图片 URL 的情况不能靠身份指纹识别；必须以索引中锁定的上游文件为准，人工审查生成结果，不能宣称随上游更新自动同步。

## 生成与审核

1. 在隔离环境按明确指定的期键和原刊期号读取只读条目快照与公开原文；不通过线上阅读请求触发。原文按固定 Git 提交获取对应文件，核对实际响应文件 SHA-256 后再解析，记录提交、文件 SHA-256、读取时间与选择依据；不能只在输出里填写未经验证的提交号。若无法可靠定位版本、源码不可取得或发生歧义，该期跳过并说明。
2. 用现行解析器和 `ImagePositions` 对上游文件解析，按期键、源、原刊期号、排序、标题、板块、链接唯一对应；源与已发布数据的候选各自出现重复键时整条跳过。完整清洗正文和原图 URL 序列需逐项相同。源行内图片、重复 URL、代码、HTML 歧义等继续遵循原解析器的保守回退。逐条记录可用或跳过原因，不根据“上图/下图”推测。
3. 生成器输出待审静态索引以及摘要报告，不写任何生产表或生成新图片文件。固定源文件及只读条目快照重新生成，输出必须逐字节一致；独立复核位置与上游原文、身份对应、索引重复、文件变更范围及异常回退。有效但错误的数组仍可能通过运行时范围检查，必须靠可重复生成、审核与测试发现。
4. 初次交付限定第 416 期。其他旧刊先按相同只读过程列出各期可恢复和跳过数，再以独立提交扩展；失败条目不影响其他刊期。生产使用现有受控发布流程；已授权第 416 期上线，不授权改写生产记录或扩展至其他刊期。

## 验收

- 离线：真实第 416 期数据重建；对 24 条逐一检查正文及 URL 序列、位置和每张图在原文中的相对段落。覆盖同内容重抓后的新 Item / Issue / Source ID、正文、URL 顺序、期键、标题、板块、排序、来源或链接变化；分别覆盖不存在位置键、显式 null 与其他已有位置、空值、超过上限、非法 URL、重复图、缺失/损坏/未知版本索引、重复键、有效但错误的人工篡改位置、非单调和越界；覆盖 emoji、空段和末尾换行。确认不写期、条目或收藏。
- 页面：真实组件在 320 / 375 / 1440 宽度显示实际图片与相邻段落；第 416 期道路路标应为“介绍 → 第一图 → 上图说明 → 后续图片及说明”，不得溢出，原图失败时正文和其余图片仍可读。验证目录、跳转、收藏、搜索、打印和减少动态效果维持原功能。单个浏览器模拟宽度不能代替真实手机或 Windows 验收。
- 完整 `bin/ci` 与资源预算、独立代码审查；只对真实执行并通过的检查作结论。部署后核对实际生产页面、健康状态和未变的历史数据。
